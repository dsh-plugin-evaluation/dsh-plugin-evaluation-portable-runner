Portable Case Plan
evaluation API.

A Portable Case Plan is one plugin evaluation scenario: it defines the setup, execution steps, and checks, then returns one structured report. The host still owns plugin execution.

01

First steps

Quick start

Install the runner in any Node.js 20+ host. The runner never starts a process or web server; your callback owns plugin execution.

npm install @dsh-plugin-evaluation/portable-runner@0.1.8
import { runPortableCasePlan } from '@dsh-plugin-evaluation/portable-runner'

const report = await runPortableCasePlan({
  plan: {
    schemaVersion: 1,
    id: 'portable-smoke',
    title: 'Portable runner smoke test',
    setup: [
      { op: 'environment.set', name: 'EXPECTED', value: 'safe' },
      { op: 'workspace.write', path: 'input.txt', content: 'fixture' },
    ],
    steps: [{ op: 'plugin.prompt', input: 'answer' }],
    metrics: [{ id: 'expected-output', type: 'output.equals', expected: 'safe' }],
  },
  async runPlugin({ env }) {
    return { output: env.EXPECTED, exitCode: 0 }
  },
})

console.log(report.status) // passed
02A

Command line

Portable Runner CLI

After installing the npm package, use portable-runner to execute a Portable Plan through an external command. The command runs without a shell and exchanges one-shot JSON files with the runner.

npx portable-runner \
  --plan ./plan.json \
  --format json \
  --timeout-ms 30000 \
  --command node -- ./adapter.mjs
INPUT

experiment.json

Written to PORTABLE_RUNNER_INPUT_DIR with input, cwd, env, and session.

OUTPUT

experiment-result.json

Read from PORTABLE_RUNNER_OUTPUT_DIR with output and execution evidence.

EXIT

0 / 1 / 2 / 124

Pass, failed checks, CLI/protocol error, or timeout.

CLI options must appear before --; everything after it is passed to the external command.

02B

API reference

runPortableCasePlan

Execute one validated Portable Case Plan and return a Runner-native report.

runPortableCasePlan(options): Promise<PortableCaseResult>
const report = await runPortableCasePlan({
  plan,
  runPlugin: async ({ input, cwd, env, session }) => ({
    output: await plugin.run({ input, cwd, env, session }),
    exitCode: 0,
  }),
  limits: { timeoutMs: 30_000, maxSteps: 100, maxMetrics: 100 },
  errorMode: 'report',
})

Required parameters

plan
Type: PortableCasePlan
One evaluation scenario with setup, steps, and metrics.
runPlugin
Type: (context) => Promise<PortablePluginExecution>
The host-owned callback that actually invokes the plugin.

Optional parameters

baseEnvironment
Default: {}
Initial environment values copied into the isolated run.
provenance
Default: {}
Caller metadata stored in the report; it does not affect checks.
secrets
Default: []
Values to detect and redact in output and evidence.

Execution options

limits.timeoutMs
Type: number
Maximum wait time for one plugin call. The host must terminate an underlying process when needed.
limits.maxSteps
Type: number
Maximum plan steps. Rejected before workspace creation when exceeded.
limits.maxMetrics
Type: number
Maximum checks. Rejected before execution when exceeded.

Failure and extension options

errorMode
Default: 'throw'
'report' converts plugin or step errors into an execution-failed check.
fixtures
Default: []
Test data and cleanup hooks selected by the plan.
stepRegistry / metricRegistry
Default: built-in registries
Register custom operations and checks.
What comes backA PortableCaseResult with status, checks, actualOutput, durationMs, provenance, and bounded evidence.
02C

Words used in the API

Terminology

These names describe responsibilities, not extra products or hidden infrastructure.

PLAN

Portable Case Plan

One evaluation scenario: preparation, plugin steps, and checks.

GROUP

PortableSuite

A group of plans that share fixtures and an aggregate report.

PREPARE

Fixture

Test data or environment setup that runs before a plan.

RUN

Step

One operation in the evaluation, such as a prompt or file write.

CHECK

Metric

A check that decides whether the collected result meets expectations.

RECORD

Evidence

Collected execution records: output, files, messages, and calls.

SOURCE

Provenance

Metadata describing which plan and caller produced the report.

EXTEND

Registry

A place to register custom steps, metrics, or report renderers.

HOST

runPlugin callback

The host-owned function that actually invokes the plugin.

04

The contract

Evaluation plans

A plan is deliberately small: bounded setup, explicit plugin steps, and reusable metrics. Use steps and metrics for all new plans.

PLAN

PortableCasePlan

Describes one deterministic evaluation case.

schemaVersion
Currently 1.
setup
environment.set, workspace.write, workspace.read.
steps
One or more plugin.prompt steps or registered operations.
metrics
At least one metric with a unique id and type.
SUITE

PortableSuite

Composes reusable cases and fixture lifecycles.

fixtures
Setup and teardown hooks shared by selected cases.
cases
Portable cases executed independently.
version
Caller-owned suite version recorded in provenance.
Compatibility noteThe legacy run plus assertions shape is normalized, but new plans should use steps plus metrics.

06

Make it yours

Customization

只有当内置能力不够时才需要这里。每个 Registry（注册表）都是一个“名称 → 实现”的清单：你注册一次，就能在计划中通过名称使用它。

const steps = createStepRegistry().register(
  'custom.prepare',
  (step, context) => { context.environment.PREPARED = String(step.value) },
)

const metrics = createMetricRegistry().register(
  'output.startsWith',
  ({ metric, output }) => output.startsWith(metric.expected),
)

const reporters = createReporterRegistry().register(
  'text',
  report => `${report.status}: ${report.summary?.passedCases ?? 0} passed`,
)
自定义步骤

createStepRegistry

给计划增加 Runner 没有内置的“动作”。例如把配置写入执行环境。

const steps = createStepRegistry().register(
  'config.set',
  (step, ctx) => { ctx.environment[step.name] = step.value },
)
// 计划中使用：{ op: 'config.set', name: 'MODE', value: 'test' }

适合：需要新的准备动作或工具动作时。

自定义评测

createMetricRegistry

给结果增加 Runner 没有内置的“判断规则”。返回 true 表示通过。

const metrics = createMetricRegistry().register(
  'output.startsWith',
  ({ output, metric }) => output.startsWith(metric.expected),
)
// 指标中使用：{ id: 'prefix', type: 'output.startsWith', expected: 'OK' }

适合：需要业务专属断言时。

自定义报告

createReporterRegistry

把评测报告转换成你的系统需要的文本格式。内置 JSON、Markdown、JUnit 已经够用时不需要注册。

const reporters = createReporterRegistry().register(
  'summary',
  report => `${report.status}: ${report.summary.passedCases} passed`,
)
const text = await reporters.render('summary', report)

适合：需要接入内部报告系统时。

07

Boundaries

Safety by construction

  • Fresh workspaceEvery invocation gets a temporary workspace removed in a finally block.
  • Bounded pathsRelative workspace paths reject NUL bytes, traversal, and escapes.
  • Host-owned executionThe callback is the trust boundary for process, network, filesystem, and credentials.
  • No DSH dependencyThe package is host-independent and never starts a process or web server.
