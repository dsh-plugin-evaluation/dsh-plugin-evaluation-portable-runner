01

First steps

Quick start

Install the runner in any Node.js 20+ host. The runner never starts a process or web server; your callback owns plugin execution.

npm install @dsh-plugin-evaluation/portable-runner@0.1.6
import { runPortableCasePlan } from '@dsh-plugin-evaluation/portable-runner'

const report = await runPortableCasePlan({
  plan: {
    schemaVersion: 1,
    id: 'portable-smoke',
    title: 'Portable runner smoke test',
    setup: [
      { op: 'environment.set', name: 'EXPECTED', value: 'safe' },
      { op: 'workspace.write', path: 'input.txt', content: 'fixture' },
    ],
    steps: [{ op: 'plugin.prompt', input: 'answer' }],
    metrics: [{ id: 'expected-output', type: 'output.equals', expected: 'safe' }],
  },
  async runPlugin({ env }) {
    return { output: env.EXPECTED, exitCode: 0 }
  },
})

console.log(report.status) // passed
02

The contract

Portable plans

A plan is deliberately small: bounded setup, explicit plugin steps, and reusable metrics. Use steps and metrics for all new plans.

PLAN

PortableCasePlan

Describes one deterministic evaluation case.

schemaVersion
Currently 1.
setup
environment.set, workspace.write, workspace.read.
steps
One or more plugin.prompt steps or registered operations.
metrics
At least one metric with a unique id and type.
SUITE

PortableSuite

Composes reusable cases and fixture lifecycles.

fixtures
Setup and teardown hooks shared by selected cases.
cases
Portable cases executed independently.
version
Caller-owned suite version recorded in provenance.
Compatibility noteThe legacy run plus assertions shape is normalized, but new plans should use steps plus metrics.
03

What comes back

Runner-native reports

Every single-case execution returns the same report contract. Hosts can persist it, render it, or pass it across an integration boundary without adapting fields.

reportSchemaVersion1
statuspassed · failed
checksStructured metric results
actualOutputFinal plugin output
summaryCases passed / failed
provenanceCaller and plan identity
evidenceFiles, calls, messages, timeout state
{
  reportSchemaVersion: 1,
  reportId: 'uuid',
  runId: 'uuid',
  status: 'passed',
  reasons: [],
  checks: [{ id: 'expected-output', passed: true }],
  actualOutput: 'safe',
  exitCode: 0,
  summary: { totalCases: 1, passedCases: 1, failedCases: 0 },
  provenance: { schemeId: 'portable-smoke', schemeVersion: 1 },
  evidence: { files: [], toolCalls: [], messages: [] }
}
04

Make it yours

Extension points

Extend the vocabulary without forking the execution loop. Registries are small, explicit, and easy to inspect.

const steps = createStepRegistry().register(
  'custom.prepare',
  (step, context) => { context.environment.PREPARED = String(step.value) },
)

const metrics = createMetricRegistry().register(
  'output.startsWith',
  ({ metric, output }) => output.startsWith(metric.expected),
)

const reporters = createReporterRegistry().register(
  'text',
  report => `${report.status}: ${report.summary?.passedCases ?? 0} passed`,
)
STEPS

createStepRegistry

Register bounded operations that receive a step and execution context.

METRICS

createMetricRegistry

Register boolean evaluators over output and collected evidence.

REPORTERS

createReporterRegistry

Render JSON, Markdown, JUnit, or a custom report format.

05

Boundaries

Safety by construction

  • Fresh workspaceEvery invocation gets a temporary workspace removed in a finally block.
  • Bounded pathsRelative workspace paths reject NUL bytes, traversal, and escapes.
  • Host-owned executionThe callback is the trust boundary for process, network, filesystem, and credentials.
  • No DSH dependencyThe package is host-independent and never starts a process or web server.
