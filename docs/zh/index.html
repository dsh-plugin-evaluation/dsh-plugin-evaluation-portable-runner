核心 API

执行与组合

FUNCTION

runPortableCasePlan()

定义于 src/index.d.ts ↗

执行一个 Portable Case Plan，并返回结构化结果。宿主负责提供 runPlugin callback。

runPortableCasePlan(options): Promise<PortableCaseResult>

参数

plan
要执行的 Portable plan。
runPlugin
接收 input、cwd、env 和 session 的 callback。
baseEnvironment
可选的初始环境变量。

返回值

Promise<PortableCaseResult>，包含状态、检查、输出、provenance 和 evidence。

const result = await runPortableCasePlan({
  plan,
  async runPlugin({ input, env }) {
    return { output: await host.run(input, env) }
  },
})
FUNCTION

runSuite()

定义于 src/index.d.ts ↗

执行 suite 中的所有 case，收集结果，并调用指定 reporter。

runSuite(options): Promise<Readonly<Record<string, unknown>>>

参数

suite
包含 case 和共享 fixture 的 suite。
reporters
接收 suite report 的命名 callback。

返回值

包含 cases、聚合 status 和通过/失败计数的 suite report。

FUNCTION

defineCase()

定义于 src/index.d.ts ↗

case 的动作和检查。

兼容性

接受旧版 run 和 assertions。新定义应使用 steps 和 metrics。

可传给 runSuite 的 PortableSuite。

01

第一步

快速开始

在 Node.js 20 或更高版本的宿主中安装 Runner。Runner 不会启动进程或 Web 服务，插件执行由你的 callback 负责。

npm install @dsh-plugin-evaluation/portable-runner@0.1.6
import { runPortableCasePlan } from '@dsh-plugin-evaluation/portable-runner'

const report = await runPortableCasePlan({
  plan: {
    schemaVersion: 1,
    id: 'portable-smoke',
    title: 'Portable runner smoke test',
    setup: [{ op: 'environment.set', name: 'EXPECTED', value: 'safe' }],
    steps: [{ op: 'plugin.prompt', input: 'answer' }],
    metrics: [{ id: 'expected-output', type: 'output.equals', expected: 'safe' }],
  },
  async runPlugin({ env }) { return { output: env.EXPECTED, exitCode: 0 } },
})

console.log(report.status) // passed
02

核心契约

Portable 评测计划

计划由受限 setup、明确的插件 steps 和可复用 metrics 组成。新计划应始终使用 steps 与 metrics。

PLAN

PortableCasePlan

描述一个确定性的评测用例。

schemaVersion
当前为 1。
setup
支持环境变量和工作区文件操作。
steps
一个或多个 plugin.prompt 或注册操作。
metrics
至少一个拥有唯一 id 和 type 的指标。
SUITE

PortableSuite

组合可复用的 cases 和 fixture 生命周期。

fixtures
共享 setup 与 teardown 钩子。
cases
独立执行的 Portable cases。
version
记录在 provenance 中的套件版本。
兼容说明旧版 run 加 assertions 仍会被规范化，但新计划应使用 steps 加 metrics。
03

执行结果

Runner-native 报告

每次单用例执行都返回统一报告契约。宿主可以直接持久化、渲染或跨集成边界传递，无需转换字段。

reportSchemaVersion1
statuspassed · failed
checks结构化指标结果
actualOutput插件最终输出
summary通过 / 失败用例数
provenance计划和调用方身份
evidence文件、调用、消息、超时状态
{
  reportSchemaVersion: 1,
  reportId: 'uuid',
  runId: 'uuid',
  status: 'passed',
  checks: [{ id: 'expected-output', passed: true }],
  actualOutput: 'safe',
  summary: { totalCases: 1, passedCases: 1, failedCases: 0 },
  provenance: { schemeId: 'portable-smoke', schemeVersion: 1 },
  evidence: { files: [], toolCalls: [], messages: [] }
}
04

按需扩展

扩展点

无需修改执行循环即可扩展词汇表。Registry 保持小而明确，也便于检查。

const steps = createStepRegistry().register(
  'custom.prepare',
  (step, context) => { context.environment.PREPARED = String(step.value) },
)

const metrics = createMetricRegistry().register(
  'output.startsWith',
  ({ metric, output }) => output.startsWith(metric.expected),
)
STEPS

createStepRegistry

注册接收 step 和执行上下文的受限操作。

METRICS

createMetricRegistry

注册基于输出和 evidence 的布尔评估器。

REPORTERS

createReporterRegistry

渲染 JSON、Markdown、JUnit 或自定义格式。

05

边界

安全边界

  • 独立工作区每次调用都会创建临时工作区，并在 finally 中删除。
  • 路径受限工作区路径必须相对，拒绝 NUL 字节、遍历和越界。
  • 宿主负责执行callback 是进程、网络、文件系统和凭证的信任边界。
  • 无 DSH 依赖包与宿主无关，不启动进程，也不启动 Web 服务。
